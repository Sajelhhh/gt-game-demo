# 浏览器横版动作游戏 SDD（MVP）

> 工作名：**Shadow Sprout**  
> 产品参考：《空洞骑士》的横版探索氛围与操作反馈；仅参考节奏和设计语言，不复制角色、地图、美术、音频或剧情。

## 1. 文档目的

本规范用于指导 Gastown 中的 Agent 团队并行开发一款可直接在现代浏览器运行的 2D 横版动作游戏。游戏应支持移动、跳跃、躲避障碍，以及与一种以上的小怪战斗。

本阶段目标是完成一个 1～2 分钟可通关、可反复试玩的小 Demo，而不是制作完整类银河战士恶魔城游戏。音频精修、深度性能优化和完整发布矩阵属于 Post-MVP。

## 2. 产品目标

玩家进入游戏后无需注册或安装，即可：

1. 操控角色左右移动和跳跃。
2. 跨越地刺、深坑或移动障碍。
3. 使用近战攻击与至少两类敌人交互。
4. 承受伤害、死亡并从检查点重新开始。
5. 到达关卡终点并看到通关反馈。

### 2.1 成功指标

- 首次加载后 5 秒内可操作（普通桌面网络环境）。
- 新玩家无需说明即可在 30 秒内完成移动、跳跃和攻击。
- 完整关卡可在 1～2 分钟内通关。
- MVP 以 Chromium 自动化验收为发布门禁；Chrome、Edge、Safari、Firefox 最新两个主版本兼容属于 Post-MVP 发布验收。
- MVP 保持流畅且无明显卡顿；60 FPS、最低 45 FPS 的固定基准测量属于 Post-MVP 发布验收。

## 3. 范围

### 3.1 MVP 范围内

- 单人、2D 横版、单关卡。
- 键盘输入。
- 左右移动、跳跃、近战攻击、受击、死亡、重生。
- 地面、平台、墙体、地刺、深坑。
- 两类敌人：巡逻型和追击型。
- 玩家生命值、敌人生命值、终点和检查点。
- 简单 HUD、开始界面、暂停、失败和通关界面。
- 占位素材或原创简易素材。

### 3.2 MVP 范围外

- 移动端触控适配。
- 联机、账号、云存档和排行榜。
- 多关卡、复杂剧情、装备、技能树、Boss。
- 程序生成地图。
- 手柄适配。
- 基础音效、背景音乐和独立音量开关（Post-MVP 增强）。
- 对象池、离屏 AI 休眠和固定设备性能基准（Post-MVP 发布优化）。
- 四浏览器完整兼容矩阵（Post-MVP 发布验收）。
- 付费、广告和数据后台。

## 4. 用户故事与验收标准

### US-01 启动游戏

作为玩家，我希望打开网页后可以快速开始游戏。

- Given 页面资源加载完成，When 玩家点击“开始游戏”，Then 进入关卡且角色可立即控制。
- 加载失败时显示可理解的错误与重试按钮。

### US-02 移动

作为玩家，我希望角色能够左右移动。

- `A/←` 向左，`D/→` 向右。
- 松开方向键后角色在短时间内减速停止，而非无限滑动。
- 角色不能穿过地面、平台或墙体。

### US-03 跳跃

作为玩家，我希望跳过坑洞和障碍。

- `Space/W/↑` 触发跳跃。
- 落地或处于允许的“土狼时间”内可完成基础跳跃；离地后可追加一次空中跳跃，落地时恢复。
- 支持约 100ms 土狼时间和约 100ms 跳跃输入缓冲，具体值可调。
- 松开跳跃键应缩短跳跃高度。

### US-04 近战攻击

作为玩家，我希望攻击敌人并获得明确反馈。

- `J/X` 触发近战攻击。
- 攻击有冷却时间，不能每帧触发。
- 每次有效攻击在朝向一侧显示短暂扩散、淡出的双层冲击波；冲击波仅提供视觉反馈，不扩大伤害判定。
- 移除矩形攻击判定框的可视占位，命中时显示短暂星形火花和扩散环。
- 正面攻击覆盖或成功命中的目标获得独立的短接触保护窗口；保护只针对该目标，不阻止背后或未命中敌人的伤害。
- 敌人受击后进入短硬直，硬直结束前 AI 不得覆盖 DamageSystem 施加的击退速度。
- 命中敌人时产生受击闪烁、击退和音效。
- 攻击判定只在攻击动画的有效帧内存在。

### US-05 与多个敌人交互

作为玩家，我希望关卡里有不止一种敌人。

- 巡逻型敌人在指定区域往返，接触玩家造成伤害。
- 追击型敌人在玩家进入感知范围后接近并攻击。
- 每类敌人均可受到攻击、扣血并死亡。
- 同屏至少支持 5 个敌人，不出现明显卡顿或状态串扰。

### US-06 障碍与伤害

作为玩家，我希望通过观察和操作避开危险。

- 地刺接触玩家造成 1 点伤害并击退。
- 跌入深坑后玩家从最近检查点恢复，并扣除生命或直接重置。
- 玩家受伤后获得约 800ms 无敌时间，避免连续碰撞瞬间死亡。

### US-07 死亡与重生

- 玩家生命值归零后进入失败状态。
- 失败界面提供“重新开始”操作。
- 重生后玩家、敌人、机关状态按设计重置。

### US-08 通关

- 玩家到达终点区域后停止战斗输入。
- 显示通关界面以及耗时、击败敌人数。
- 可选择重新开始。

### US-09 暂停与音频

- `Esc` 暂停或恢复。
- 暂停时物理、AI、动画、Tween、冷却、无敌窗和关卡计时全部停止。
- 玩家可分别开启或关闭音乐和音效（Post-MVP；不阻塞小 Demo）。

## 5. 游戏规则

### 5.1 初始参数

所有参数必须集中配置，禁止散落魔法数字。

| 参数 | 初始值 |
|---|---:|
| 玩家最大生命 | 5 |
| 移动速度 | 220 px/s |
| 跳跃速度 | 430 px/s |
| 空中追加跳跃 | 1 次 |
| 重力 | 1200 px/s² |
| 攻击冷却 | 350 ms |
| 玩家攻击伤害 | 1 |
| 受击无敌时间 | 800 ms |
| 普通敌人生命 | 2～3 |

参数为首版建议值，最终以手感测试为准。

### 5.2 状态机

玩家状态：`idle`、`run`、`jump`、`fall`、`attack`、`hurt`、`dead`。

敌人状态：`idle`、`patrol`、`chase`、`attack`、`hurt`、`dead`。

规则：

- `dead` 是终止状态，不再接受移动和战斗输入。
- `hurt` 期间限制输入，结束后回到可控状态。
- 攻击、受击、死亡转换必须由明确事件驱动，不依赖动画名隐式判断。

## 6. 关卡规范

MVP 仅包含一张线性关卡：

1. 安全出生区：展示键位提示。
2. 基础跳跃区：低平台和单个 60px 深坑；坑洞伤害触发区必须位于地面表面以下，避免形成不可见伤害墙。
3. 首次战斗区：1～2 个巡逻敌人。
4. 组合挑战区：地刺、平台和追击敌人。
5. 检查点。
6. 最终战斗区：两类敌人同时出现。
7. 终点区域。

关卡必须保证：

- 所有必经跳跃都能用基础能力完成。
- 摄像机不会展示地图外空白区域。
- 出生点与检查点不可放在敌人攻击范围或危险碰撞体内。
- 不要求玩家利用 Bug 或像素级操作通关。

## 7. 非功能需求

### 7.1 性能

- 小 Demo 只允许数量有上限的短生命周期攻击特效；对象池在 Post-MVP 发布优化中完成。
- 视口外敌人降频或休眠属于 Post-MVP 发布优化。
- 首屏压缩资源目标不超过 10 MB。
- 禁止在每帧循环中创建大量临时对象。

### 7.2 可维护性

- TypeScript 开启严格模式。
- 游戏数值集中在配置文件。
- 输入、角色、战斗、敌人 AI、关卡和 UI 分层。
- 核心规则提供单元测试；主流程提供浏览器端冒烟测试。

### 7.3 可访问性

- 不只用颜色表达受伤或危险。
- 提供音量开关。
- UI 文字与背景满足基本对比度要求。
- 高频闪烁效果必须受限。

## 8. 目标架构

### 8.1 技术栈

- 构建：Vite
- 语言：TypeScript
- 游戏引擎：Phaser 3
- 物理：Phaser Arcade Physics
- 地图：Tiled JSON 或代码生成的静态 Tilemap
- 测试：Vitest + Playwright
- 代码质量：ESLint + Prettier

选择 Arcade Physics 的原因：MVP 只需要 AABB 碰撞和简单平台运动，它比 Matter.js 更轻、更容易调试。

### 8.2 模块划分

公共架构的规范性定义见 [`browser_platformer_architecture_contract.md`](./browser_platformer_architecture_contract.md)。F-02 必须先实现其中的配置、事件、碰撞和状态契约，再扩展 Scene 骨架。

### 8.3 关键约束

- `GameScene` 只负责编排，不堆积角色和战斗细节。
- Arcade Physics 回调只收集碰撞候选；`CombatCoordinator` 按“玩家有效攻击 → 敌人攻击 → 延迟接触伤害”裁决，避免依赖引擎回调顺序。
- 伤害统一通过 `DamageSystem.applyDamage()` 进入，禁止各实体直接修改对方生命值。
- 玩家与敌人通过类型化事件通信；事件名、payload、唯一 emitter 和清理生命周期以公共架构契约第 5 节为准。
- Arcade Physics 的 Tilemap 层必须命名为 `World`、`Hazard`；`Player`、`Enemy`、`PlayerAttack`、`EnemyAttack` 是 group/category 业务名，不是 Matter bitmask。完整矩阵以公共架构契约第 6 节为准。
- 模块依赖只能沿公共架构契约第 2 节方向；system 不导入具体 Player/Enemy，公共 contracts/config 不依赖 Phaser。
- `UIScene`/交互层是 `restart-requested` 的唯一 emitter；`GameScene` 只监听并按失败/通关语义重建生命周期。
- 美术资源使用自制、CC0 或明确授权素材，并记录来源。

## 9. 测试规范

### 9.1 单元测试

- 生命值不低于 0、不高于最大值。
- 无敌时间内重复伤害被忽略。
- 攻击冷却未结束时不能再次攻击。
- 状态机拒绝非法状态转换。
- 检查点更新后重生位置正确。

### 9.2 集成与 E2E

- 页面可加载并进入游戏。
- 玩家可移动、跳跃并通过第一个障碍。
- 玩家攻击能使敌人扣血并死亡。
- 玩家触碰地刺后扣血且不会瞬间连续扣血。
- 玩家死亡后可以重新开始。
- 到达终点后显示通关界面。
- 暂停后实体位置和关卡计时不再变化。

### 9.3 完成定义（DoD）

一项任务只有同时满足以下条件才算完成：

- 实现符合本规范和验收标准。
- TypeScript 编译无错误。
- Lint、单元测试、E2E 冒烟测试通过。
- 没有阻塞级控制台错误。
- 新增配置和模块有必要注释。
- 若改变玩法，已同步修改本规范。

## 12. 已冻结的 MVP 决策

以下选择在 Queue 0 冻结；详细接口与边界见公共架构契约第 7 节：

1. 主角设定与最终美术不阻塞工程；MVP 使用原创占位资产或有授权记录的素材。
2. 根据试玩反馈，MVP 加入一次空中追加跳跃（二段跳），不加入冲刺。
3. 玩家碰到敌人时造成 1 点接触伤害，统一进入 `DamageSystem`。
4. 坠坑扣 1 点生命并回最近检查点；致死时进入失败流程。
5. MVP 仅支持桌面键盘，不做移动端适配。
6. 小 Demo 目标时长为 1～2 分钟；音频、对象池/离屏休眠和四浏览器发布矩阵不阻塞核心试玩。
